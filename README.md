# B U D D Y code

## فكرة المشروع
منصة تعليمية تفاعلية للأطفال تعتمد على الألعاب لتعليم أسس البرمجة بطريقة ممتعة وتدريجية.

## الهدف
تجهيز طفل من المبتدئ إلى مستوى أكثر تقدماً عبر:
- الأوامر الأساسية
- التكرار والحلقات
- الشروط والمنطق
- التفكير وحل المشكلات
- المشاريع الصغيرة

## بنية المشروع
- `index.html` : نقطة الدخول الرئيسية للمنصة
- `pages/index/` : الصفحة الرئيسية
- `pages/games/` : قسم الألعاب وبطاقاته
- `pages/maze/` : لعبة CoD، عشرون مستوى متدرجًا باستخدام أوامر الاتجاه والتكرار والقفز، تتوسع شبكاتها من 5×5 إلى 10×10، مع حيوان وطعام مختلفين كل خمسة مستويات وقفل المراحل التالية حتى إكمال السابقة
- `pages/draw/` : عشرة ألغاز رسم مسار من الشخصية إلى الهدف مع تجنب العوائق
- `pages/frog/` : خمسة مستويات متدرجة للقفز بين أوراق الزنبق وجمع الحشرات
- `pages/gas/` : لعبة مهندس الجسور والمعدّيات
- `pages/robot/` : لعبة B U D D Y code وتعليم أوامر البرمجة
- `pages/lesson/` : خمسة دروس برمجية تُفتح حسب عدد المستويات المكتملة
- `pages/common.css` : الأنماط المشتركة
- `pages/common.js` : حفظ تقدم اللاعب

يبني الطفل المعبر بسحب قطع الجسر إلى خانات النهر (أو بالنقر عليها)، ثم يشغّل البرنامج لترى العربة تعبر من نقطة البداية إلى الهدف. تعرض اللعبة المشهد بمجسمات WebGL ثلاثية الأبعاد بخامات خشب وخرسانة وماء، ويمكن تدوير زاوية الرؤية بسحب المشهد؛ إذا لم يدعم المتصفح WebGL، تبقى الرسوم ثنائية الأبعاد بديلًا. تتدرج اللعبة في عشرة مستويات لتعليم تسلسل الأوامر، التكرار، شروط إذا/وإلا بحسب حالة النهر، وتصحيح الأخطاء واختصار البرنامج. تعرض المستويات تلميحات تناسب مراحل عمرية تقريبية (6–8، 9–11، 12–15) من دون منع أي طفل من تجربة التحديات.

تُحسب النجوم وتُعرض بصورة مستقلة لكل لعبة، بينما يعرض ملخص المنصة مجموع نجوم الألعاب.

## إضافة لعبة
أضف صفحة اللعبة داخل `pages/` ثم أضف عنصرًا إلى `gameCatalog` في `pages/common.js` يتضمن المفتاح والعنوان والرمز والرابط وعدد المستويات واللون. سيظهر العنصر تلقائيًا في قسم الألعاب، ويدخل عدد مستوياته في ملخص التقدم.

### تثبيت التطبيق على الهاتف

يدعم الموقع التثبيت كتطبيق ويب (PWA). انشره على HTTPS؛ التثبيت عبر الهاتف يتطلب اتصالًا آمنًا (ويُستثنى localhost للتجربة على الكمبيوتر). في Chrome أو Edge اضغط «تثبيت التطبيق» ثم وافق على نافذة التثبيت؛ يجب تأكيد التثبيت من المتصفح ولا يمكن تجاوزه برمجيًا. عارض VS Code لا يدعم نافذة التثبيت، لذا افتح رابط الموقع في Chrome أو Edge. في iPhone/iPad افتح الموقع في Safari، واضغط «مشاركة» ثم «إضافة إلى الشاشة الرئيسية». تظهر إرشادات التثبيت أسفل الزر عند الحاجة.

عند تفعيل إصدار جديد من Service Worker، يظهر إشعار «تحديث متاح» مع خيار إعادة تحميل التطبيق. يحذف Service Worker كاشات ملفات التطبيق القديمة فقط؛ تقدم الألعاب والنجوم محفوظة في Firestore تحت معرّف Firebase Auth لكل مستخدم.

يُعاد تحميل الصفحات تلقائيًا عند تبديل Service Worker إذا لم تكن هناك تغييرات غير محفوظة في النماذج؛ عند وجود تغييرات، يبقى إشعار التحديث ظاهرًا ويطلب تأكيدًا قبل إعادة التحميل. يفحص التطبيق وجود تحديث عند فتحه وعند العودة إلى تبويبه، لكن لا يمكنه تنزيل تحديث أثناء إغلاق التطبيق أو دون اتصال. غيّر `APP_VERSION` في `sw.js` مع كل إصدار منشور.

يستخدم Service Worker كاشًا سريعًا للملفات الثابتة وملفات App Shell الأساسية، ويحدّث `manifest.webmanifest` في الخلفية. إعدادات Firebase وطلبات API لا تُخزّن في Cache Storage، ويُجرى فحص Service Worker بحد أقصى مرة كل خمس دقائق لكل تبويب.

التقدم وإعدادات الألعاب والدروس والحسابات لا تُحفظ في `localStorage`؛ Firestore هو مصدر البيانات الدائمة، وFirebase Auth يدير جلسة الدخول. قد تبقى مفاتيح قديمة من إصدارات سابقة في متصفح المستخدم، لكن التطبيق لا يقرأها ولا يدمجها ولا يحذفها تلقائيًا. يستخدم `sessionStorage` فقط لتوقيت فحص تحديث Service Worker، بينما يستخدم Service Worker Cache Storage للملفات الثابتة دون بيانات المستخدم. عند فشل Firebase لا يوجد حفظ محلي بديل، وتظهر رسالة خطأ.

تُستعاد جلسة Firebase Auth على كل جهاز وفق إعداد الاستمرارية الخاص بـ Firebase؛ سجّل الدخول بحسابك على كل جهاز لمزامنة بيانات Firestore. يتطلب Service Worker وميزات تثبيت PWA اتصال HTTPS، بينما يعمل `localhost` كاستثناء آمن للتطوير.

## إدارة المستخدمين وحفظ تقدمهم سحابيًا

يعمل الموقع الثابت على GitHub Pages مع Firebase Authentication وCloud Firestore لحفظ تقدم كل حساب تحت UID الخاص به، واستعادته عند تسجيل الدخول من جهاز آخر. ينشئ التسجيل الحساب مباشرة عبر Firebase Authentication، ثم يحفظ ملف المستخدم في Firestore؛ ولا يستدعي الموقع Cloud Functions. تستخدم الحسابات الجديدة البريد الداخلي `username@kids-games.local` وكلمة المرور المدخلة (PIN من 6 أرقام على الأقل). يختار المستخدم الاسم واسم المستخدم والرمز والشخصية والدور (طفل أو معلم أو ولي أمر)، ويُفعّل الدور مباشرة عند التسجيل. يدعم تسجيل الدخول أيضًا الحسابات القديمة المنشأة بالبريد الداخلي `username@accounts.kids-games.invalid`. لا يمكن لهذه العناوين استقبال البريد.

تتيح لوحة المدير البحث والتصفية وإنشاء الحسابات وإدارة أدوارها وحالاتها مباشرة عبر Firebase Auth وFirestore. التعطيل يمنع الحساب من الدخول إلى التطبيق لكنه لا يحذف هوية Firebase Auth. لا يمكن تغيير كلمة مرور مستخدم آخر أو اسم المستخدم من التطبيق؛ وتغيير كلمة مرور المستخدم نفسه يتم عبر Firebase Auth بعد إعادة التحقق من كلمة المرور الحالية.

يمكن لكل مستخدم فتح «ملفي الشخصي» من قائمة الحساب لتغيير الاسم والشخصية. كما يمكن لحسابات اسم المستخدم تغيير رمز PIN (6 أرقام على الأقل) أو كلمة المرور الحالية (6 إلى 128 حرفًا) عبر Cloud Function `updateOwnProfile`، مع التحقق من بيانات الدخول الحالية وتحديث Firebase Auth وFirestore. تظل رموز PIN القديمة ذات 4 أرقام صالحة لتسجيل الدخول والتحقق من بيانات الدخول الحالية، لكن لا يمكن تعيينها كرمز جديد. قد تتطلب بعض الحسابات القديمة إعادة التحقق بكلمة المرور الحالية. الحسابات المرتبطة بـ Google تغيّر كلمة مرورها من Google، ويمكنها تعديل الاسم والشخصية من التطبيق.

تتيح صفحة «نسيت كلمة المرور؟» إرسال رابط إعادة التعيين من Firebase Auth إلى الإيميل الحقيقي المرتبط بالحساب. حسابات اسم المستخدم تستخدم عناوين داخلية تنتهي بـ `.local` أو `.invalid` ولا يمكنها استقبال البريد؛ لا تستخدم هذه العناوين لإعادة التعيين. إذا لم يكن للحساب إيميل حقيقي، اطلب من المدير إعادة تعيين كلمة المرور من لوحة الإدارة.

### تجهيز Firebase للنشر

1. أنشئ مشروع Firebase، وأضف تطبيق Web، وأنشئ قاعدة Firestore في وضع الإنتاج. انسخ إعدادات Web العامة إلى `firebase-config.json`؛ هذه الإعدادات ليست مفتاح Admin ولا تحتوي بيانات اعتماد سرية.
2. ثبّت Firebase CLI، وسجّل الدخول، واختر مشروعك من مجلد المشروع:

   ```powershell
   npm install -g firebase-tools
   firebase login
   firebase use --add
   ```

3. فعّل مزوّد Email/Password في Firebase Authentication. يتطلب نشر Cloud Functions خطة Firebase مع فوترة مفعّلة وقد تترتب عليه تكاليف حسب الاستخدام؛ راجع أسعار Firebase قبل النشر. بعد ذلك انشر الدوال وقواعد Firestore:

   ```powershell
   firebase deploy --only functions,firestore:rules
   ```

4. أنشئ مفتاح خدمة Firebase Admin واحفظه خارج مجلد المشروع، ولا ترفعه إلى GitHub. من PowerShell، عيّن مسار المفتاح واسم المدير وكلمة مروره ثم شغّل أداة إنشاء المدير الأول:

   ```powershell
   $env:GOOGLE_APPLICATION_CREDENTIALS = 'C:\secure\firebase-admin.json'
   $env:BOOTSTRAP_ADMIN_USERNAME = Read-Host 'اسم مستخدم المدير'
   $env:BOOTSTRAP_ADMIN_PASSWORD = [Net.NetworkCredential]::new('', (Read-Host 'كلمة مرور المدير' -AsSecureString)).Password
   npm --prefix functions run bootstrap-admin
   Remove-Item Env:BOOTSTRAP_ADMIN_USERNAME, Env:BOOTSTRAP_ADMIN_PASSWORD
   ```

   اختر كلمة مرور قوية من 6 إلى 128 حرفًا. تنشئ الأداة حساب Firebase والملف السحابي وادعاء Firebase المخصص `admin: true` المطلوب لصلاحية المدير، وتعمل مرة واحدة فقط قبل إنشاء أي مدير. لا تُنشئ حساب المدير يدويًا من واجهة الموقع أو Firestore؛ إذ يجب أن تكون له صلاحية خادمية ليتمكن من إدارة الحسابات والإعدادات.

5. سجّل الدخول من أي جهاز باستخدام اسم المستخدم وكلمة المرور اللذين أدخلتهما عند إنشاء المدير؛ يُوجّه حساب المدير مباشرةً إلى لوحة الإدارة، بينما يدخل باقي المستخدمين إلى الصفحة الرئيسية. تتزامن إعدادات الدروس والألعاب والتقدم بين الأجهزة عبر Firestore.
6. انشر ملفات الموقع إلى GitHub Pages. لا يحتاج نشر الموقع إلى Firebase Hosting.

### التحقق والأمان

- لا ترفع `node_modules` أو بيانات اعتماد خاصة إلى GitHub. يعتمد نشر Cloud Functions على الحزم المعرفة في `functions/package.json`.
- لا تُعامل `firebase-config.json` على أنه سر؛ يحتاجه الموقع لبدء Firebase، كما يحتاج Firebase CLI إلى `firebase.json` لنشر الدوال والقواعد. لا تضع مفتاح خدمة Firebase Admin أو بيانات اعتماده في ملفات الموقع أو Git.
- تمنع قواعد Firestore الكتابة غير المصرح بها، ولا تسمح بعمليات الإدارة إلا لمستخدم مسجل يحمل ادعاء Firebase المخصص `admin: true` وملف مدير نشط. يختار الحساب الجديد دور طفل أو معلم أو ولي أمر عند التسجيل، ويُمنع تغيير الدور بعد ذلك إلا بواسطة المدير. لا يمكن إنشاء حساب مدير من واجهة الموقع؛ ويُحدد المدير الأول باستخدام أداة الإعداد.
- لا توجد حسابات تجريبية أو مسارات تسجيل دخول محلية في إصدار الموقع؛ يلزم اتصال Firebase للمصادقة وحفظ البيانات.
- تعرض ألعاب المراحل شريط اختيار أفقيًا صغيرًا يوضح المكتمل والمفتوح والمقفل، وتُفتح المراحل بالتتابع للمستخدم غير المدير؛ ويستطيع المدير اختيار أي مستوى. تعرض ملاهي البرمجة مهامها الخمس في الشريط نفسه، وتُفتح المهمة التالية بعد إكمال السابقة.
- تحتوي صفحة الدروس على خمسة دروس جاهزة برسوم توضيحية محلية في الأوامر والتسلسل والتكرار والشروط وتصحيح الأخطاء. يحدد المدير من لوحة الإدارة عدد المستويات المكتملة المطلوب لفتح كل درس؛ وتُحفظ الإعدادات في Firestore.
- يستطيع المدير إيقاف لعبة مؤقتًا للتحديث من لوحة الإدارة؛ تُحفظ الحالة في `settings/games` وتُتاح قراءتها للمستخدمين المسجلين وكتابتها للمدير النشط.
- يتضمن قسم وضع الصيانة في لوحة الإدارة مفتاح تشغيل ورسالة ووقت عودة متوقعًا اختياريًا؛ تُحفظ الحالة في `settings/site` وتصل إلى الصفحات المفتوحة عبر Firestore listener. تبقى صفحة تسجيل الدخول متاحة ليتمكن المدير من الدخول وإيقاف الصيانة من أي جهاز.
- إذا لم تتوفر إعدادات Firebase أو الاتصال أو الصلاحيات، لا يحفظ التطبيق بيانات المستخدم محليًا ولا يسمح بالاستمرار كأن الحفظ نجح.
