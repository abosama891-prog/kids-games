# Kids Games Learning Platform

## فكرة المشروع
منصة تعليمية تفاعلية للأطفال تعتمد على الألعاب لتعليم أسس البرمجة بطريقة ممتعة وتدريجية.

## الهدف
تجهيز طفل من المبتدئ إلى مستوى أكثر تقدماً عبر:
- الأوامر الأساسية
- التكرار والحلقات
- الشروط والمنطق
- التفكير وحل المشكلات
- المشاريع الصغيرة

## بنية المشروع
- `index.html` : نقطة الدخول الرئيسية للمنصة
- `pages/index/` : الصفحة الرئيسية
- `pages/games/` : قسم الألعاب وبطاقاته
- `pages/maze/` : لعبة المتاهة
- `pages/draw/` : عشرة ألغاز رسم مسار من الشخصية إلى الهدف مع تجنب العوائق
- `pages/gas/` : لعبة مهندس الجسور والمعدّيات
- `pages/robot/` : لعبة 🌈 B u d d y 🌈 وتعليم أوامر البرمجة
- `pages/lesson/` : الدروس التعليمية
- `pages/common.css` : الأنماط المشتركة
- `pages/common.js` : حفظ تقدم اللاعب

يبني الطفل المعبر بسحب قطع الجسر إلى خانات النهر (أو بالنقر عليها)، ثم يشغّل البرنامج لترى العربة تعبر من نقطة البداية إلى الهدف. تتدرج اللعبة في عشرة مستويات لتعليم تسلسل الأوامر، التكرار، شروط إذا/وإلا بحسب حالة النهر، وتصحيح الأخطاء واختصار البرنامج. تعرض المستويات تلميحات تناسب مراحل عمرية تقريبية (6–8، 9–11، 12–15) من دون منع أي طفل من تجربة التحديات.

تُحسب النجوم وتُعرض بصورة مستقلة لكل لعبة، بينما يعرض ملخص المنصة مجموع نجوم الألعاب.

## إضافة لعبة
أضف صفحة اللعبة داخل `pages/` ثم أضف عنصرًا إلى `gameCatalog` في `pages/common.js` يتضمن المفتاح والعنوان والرمز والرابط وعدد المستويات واللون. سيظهر العنصر تلقائيًا في قسم الألعاب، ويدخل عدد مستوياته في ملخص التقدم.

## التشغيل
افتح الملف التالي في المتصفح:
- `index.html`

أو استخدم خادم ثابت مثل:
- `python -m http.server 8000`

ثم افتح:

## إدارة المستخدمين وحفظ تقدمهم سحابيًا

يعمل الموقع الثابت على GitHub Pages مع Firebase Authentication وCloud Firestore لحفظ تقدم كل حساب تحت UID الخاص به، واستعادته عند تسجيل الدخول من جهاز آخر. حسابات اسم المستخدم وكلمة المرور تُوثّق عبر Firebase Cloud Functions؛ تُخزّن كلمات المرور مجزأة بـ scrypt في مجموعة خاصة لا يستطيع المتصفح قراءتها. لا ترفع كلمات المرور أو مفتاح خدمة Firebase إلى GitHub.

تتيح لوحة المدير السحابية إضافة الحسابات وتعديلها وتعطيلها وحذفها، والبحث والتصفية حسب الدور. البريد اختياري. عند نقل حساب محلي قديم إلى حساب سحابي بالاسم نفسه، يحاول التطبيق دمج التقدم المحلي القديم عند أول تسجيل دخول. لا تُنقل كلمات مرور الحسابات المحلية تلقائيًا؛ أنشئ الحسابات السحابية من جديد بكلمات مرورها عبر مدير السحابة.

### تجهيز Firebase للنشر

1. أنشئ مشروع Firebase، وأضف تطبيق Web، وأنشئ قاعدة Firestore في وضع الإنتاج. انسخ إعدادات Web العامة إلى `firebase-config.json`؛ هذه الإعدادات ليست مفتاح Admin ولا تحتوي بيانات اعتماد سرية.
2. ثبّت Firebase CLI، وسجّل الدخول، واختر مشروعك من مجلد المشروع:

   ```powershell
   npm install -g firebase-tools
   firebase login
   firebase use --add
   ```

3. فعّل خطة Firebase التي تدعم Cloud Functions (قد تتطلب خطة Blaze)، ثم ثبّت واعرض ملفات الدوال والقواعد:

   ```powershell
   npm --prefix functions install
   firebase deploy --only firestore:rules,functions
   ```

4. أنشئ اعتماد Admin SDK محليًا من Google Cloud/Firebase، واحفظ ملف الخدمة **خارج مجلد المشروع**. لا ترفعه إلى المستودع. افتح PowerShell واضبط متغيرات أول مدير ثم شغّل التهيئة مرة واحدة:

   ```powershell
   $env:GOOGLE_APPLICATION_CREDENTIALS = 'C:\secure\firebase-admin.json'
   $env:BOOTSTRAP_ADMIN_USERNAME = 'admin'
   $env:BOOTSTRAP_ADMIN_PASSWORD = 'كلمة-مرور-قوية-وجديدة'
   npm --prefix functions run bootstrap-admin
   ```

   اختر كلمة مرور قوية ولا تستخدم بيانات المدير التجريبية `admin/admin123`. بعد التهيئة احذف متغير كلمة المرور من الجلسة (`Remove-Item Env:BOOTSTRAP_ADMIN_PASSWORD`).

5. سجّل الدخول بحساب المدير الجديد، ثم أضف بقية الحسابات من لوحة الإدارة. الحسابات التجريبية القديمة الموجودة في `localStorage` ليست حسابات سحابية، ولن تعمل على الأجهزة الأخرى حتى تُنشأ في Firebase.
6. انشر ملفات الموقع إلى GitHub Pages. لا يحتاج نشر الموقع إلى Firebase Hosting. أضف نطاق الموقع إلى Authorized domains في Firebase Authentication إذا استخدمت تسجيل Google.

### التحقق والأمان

- اختبر دوال الخادم محليًا: `npm --prefix functions test`.
- تُمنع قواعد Firestore المتصفح من قراءة مجموعة الحسابات/تجزئات كلمات المرور، وتسمح للمستخدم بقراءة وكتابة مستند تقدمه فقط. عمليات إدارة الحسابات تتحقق من مطالبة المدير في Firebase ID token داخل Cloud Functions.
- المستوى التالي لا يُفتح للمستخدم غير المدير إلا بعد إكمال السابق في اللعبة نفسها؛ ويستطيع المدير فتح كل المستويات.
- إذا لم تُملأ إعدادات `firebase-config.json` أو لم تُنشر Cloud Functions والقواعد، يعمل الموقع محليًا فقط ولا توجد مزامنة سحابية.
