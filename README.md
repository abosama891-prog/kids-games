# 🌈 B u d d y 🌈

## فكرة المشروع
منصة تعليمية تفاعلية للأطفال تعتمد على الألعاب لتعليم أسس البرمجة بطريقة ممتعة وتدريجية.

## الهدف
تجهيز طفل من المبتدئ إلى مستوى أكثر تقدماً عبر:
- الأوامر الأساسية
- التكرار والحلقات
- الشروط والمنطق
- التفكير وحل المشكلات
- المشاريع الصغيرة

## بنية المشروع
- `index.html` : نقطة الدخول الرئيسية للمنصة
- `pages/index/` : الصفحة الرئيسية
- `pages/games/` : قسم الألعاب وبطاقاته
- `pages/maze/` : لعبة المتاهة
- `pages/draw/` : عشرة ألغاز رسم مسار من الشخصية إلى الهدف مع تجنب العوائق
- `pages/gas/` : لعبة مهندس الجسور والمعدّيات
- `pages/robot/` : لعبة 🌈 B u d d y 🌈 وتعليم أوامر البرمجة
- `pages/lesson/` : خمسة دروس برمجية تُفتح حسب عدد المستويات المكتملة
- `pages/common.css` : الأنماط المشتركة
- `pages/common.js` : حفظ تقدم اللاعب

يبني الطفل المعبر بسحب قطع الجسر إلى خانات النهر (أو بالنقر عليها)، ثم يشغّل البرنامج لترى العربة تعبر من نقطة البداية إلى الهدف. تعرض اللعبة المشهد بمجسمات WebGL ثلاثية الأبعاد بخامات خشب وخرسانة وماء، ويمكن تدوير زاوية الرؤية بسحب المشهد؛ إذا لم يدعم المتصفح WebGL، تبقى الرسوم ثنائية الأبعاد بديلًا. تتدرج اللعبة في عشرة مستويات لتعليم تسلسل الأوامر، التكرار، شروط إذا/وإلا بحسب حالة النهر، وتصحيح الأخطاء واختصار البرنامج. تعرض المستويات تلميحات تناسب مراحل عمرية تقريبية (6–8، 9–11، 12–15) من دون منع أي طفل من تجربة التحديات.

تُحسب النجوم وتُعرض بصورة مستقلة لكل لعبة، بينما يعرض ملخص المنصة مجموع نجوم الألعاب.

## إضافة لعبة
أضف صفحة اللعبة داخل `pages/` ثم أضف عنصرًا إلى `gameCatalog` في `pages/common.js` يتضمن المفتاح والعنوان والرمز والرابط وعدد المستويات واللون. سيظهر العنصر تلقائيًا في قسم الألعاب، ويدخل عدد مستوياته في ملخص التقدم.

### تثبيت التطبيق على الهاتف

يدعم الموقع التثبيت كتطبيق ويب (PWA). انشره على HTTPS؛ التثبيت عبر الهاتف يتطلب اتصالًا آمنًا (ويُستثنى localhost للتجربة على الكمبيوتر). في Chrome أو Edge اضغط «تثبيت التطبيق» ثم وافق على نافذة التثبيت؛ يجب تأكيد التثبيت من المتصفح ولا يمكن تجاوزه برمجيًا. عارض VS Code لا يدعم نافذة التثبيت، لذا افتح رابط الموقع في Chrome أو Edge. في iPhone/iPad افتح الموقع في Safari، واضغط «مشاركة» ثم «إضافة إلى الشاشة الرئيسية». تظهر إرشادات التثبيت أسفل الزر عند الحاجة.

## إدارة المستخدمين وحفظ تقدمهم سحابيًا

يعمل الموقع الثابت على GitHub Pages مع Firebase Authentication وCloud Firestore لحفظ تقدم كل حساب تحت UID الخاص به، واستعادته عند تسجيل الدخول من جهاز آخر. لا يحتاج المشروع إلى Cloud Functions. ينشئ المدير حسابات Email/Password من Firebase Console؛ يكتب المستخدم اسم المستخدم وكلمة المرور في الموقع، ويحوّل التطبيق اسم المستخدم إلى معرّف دخول بالشكل `username@accounts.kids-games.invalid`. هذا البريد افتراضي لتسجيل الدخول ولا يستقبل الرسائل.

تتيح لوحة المدير السحابية البحث والتصفية وتعديل أدوار الحسابات وحالتها. إنشاء الحسابات وكلمات المرور وحذف الحسابات تتم من Firebase Console. عند نقل حساب قديم، حدّث بريده في Firebase Authentication إلى المعرّف الافتراضي أعلاه واضبط كلمة مرور له مع الاحتفاظ بـ UID نفسه؛ يدمج التطبيق التقدم المحلي القديم عند أول تسجيل دخول.

### تجهيز Firebase للنشر

1. أنشئ مشروع Firebase، وأضف تطبيق Web، وأنشئ قاعدة Firestore في وضع الإنتاج. انسخ إعدادات Web العامة إلى `firebase-config.json`؛ هذه الإعدادات ليست مفتاح Admin ولا تحتوي بيانات اعتماد سرية.
2. ثبّت Firebase CLI، وسجّل الدخول، واختر مشروعك من مجلد المشروع:

   ```powershell
   npm install -g firebase-tools
   firebase login
   firebase use --add
   ```

3. فعّل مزوّد Email/Password في Firebase Authentication، ثم انشر قواعد Firestore:

   ```powershell
   firebase deploy --only firestore:rules
   ```

4. أنشئ حساب المدير الأول من Authentication > Users في Firebase Console، مستخدمًا مثلًا البريد `admin@accounts.kids-games.invalid` وكلمة مرور قوية. انسخ UID ثم أنشئ مستندًا في Firestore داخل مجموعة `users`، واجعل معرّف المستند هو UID، وأضف الحقول:

   ```json
   {
     "username": "admin",
     "email": "admin@accounts.kids-games.invalid",
     "fullName": "المدير",
     "role": "admin",
     "provider": "local",
     "status": "active",
     "progress": {}
   }
   ```

   أنشئ بقية المستخدمين من Authentication > Users باستخدام البريد الافتراضي الموافق لاسم كل مستخدم. ينشئ التطبيق ملفاتهم في Firestore عند أول تسجيل دخول، بدور `child`.

5. سجّل الدخول باسم المستخدم `admin` وكلمة المرور التي أنشأتها. الحسابات التجريبية القديمة في `localStorage` ليست حسابات سحابية؛ أنشئها في Firebase Authentication واضبط البريد الافتراضي وكلمة المرور يدويًا.
6. انشر ملفات الموقع إلى GitHub Pages. لا يحتاج نشر الموقع إلى Firebase Hosting. أضف نطاق الموقع إلى Authorized domains في Firebase Authentication إذا استخدمت تسجيل Google.

### التحقق والأمان

- لا ترفع `node_modules` أو بيانات اعتماد خاصة إلى GitHub. لا يحتاج المشروع إلى تثبيت حزم npm ليتصل بـ Firebase.
- تسمح قواعد Firestore للمستخدم بالوصول إلى ملفه وتقدمه فقط. يُسمح للمدير بقراءة الملفات وتعديل الدور والحالة، ويُحدد المدير الأول يدويًا من Firebase Console. لا يمكن ترقية الحساب إلى مدير من واجهة الموقع.
- المستوى التالي لا يُفتح للمستخدم غير المدير إلا بعد إكمال السابق في اللعبة نفسها؛ ويستطيع المدير فتح كل المستويات.
- تحتوي صفحة الدروس على خمسة دروس جاهزة برسوم توضيحية محلية في الأوامر والتسلسل والتكرار والشروط وتصحيح الأخطاء. يحدد المدير من لوحة الإدارة عدد المستويات المكتملة المطلوب لفتح كل درس؛ وتُحفظ الإعدادات سحابيًا مع Firebase أو محليًا عند عدم تفعيلها.
- إذا لم تُملأ إعدادات `firebase-config.json` أو لم تُنشر القواعد، يعمل الموقع محليًا فقط ولا توجد مزامنة سحابية.
