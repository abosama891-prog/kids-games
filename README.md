# B U D D Y code

## فكرة المشروع
منصة تعليمية تفاعلية للأطفال تعتمد على الألعاب لتعليم أسس البرمجة بطريقة ممتعة وتدريجية.

## الهدف
تجهيز طفل من المبتدئ إلى مستوى أكثر تقدماً عبر:
- الأوامر الأساسية
- التكرار والحلقات
- الشروط والمنطق
- التفكير وحل المشكلات
- المشاريع الصغيرة

## بنية المشروع
- `index.html` : نقطة الدخول الرئيسية للمنصة
- `pages/index/` : الصفحة الرئيسية
- `pages/games/` : قسم الألعاب وبطاقاته
- `pages/maze/` : لعبة المتاهة
- `pages/draw/` : عشرة ألغاز رسم مسار من الشخصية إلى الهدف مع تجنب العوائق
- `pages/gas/` : لعبة مهندس الجسور والمعدّيات
- `pages/robot/` : لعبة B U D D Y code وتعليم أوامر البرمجة
- `pages/lesson/` : خمسة دروس برمجية تُفتح حسب عدد المستويات المكتملة
- `pages/common.css` : الأنماط المشتركة
- `pages/common.js` : حفظ تقدم اللاعب

يبني الطفل المعبر بسحب قطع الجسر إلى خانات النهر (أو بالنقر عليها)، ثم يشغّل البرنامج لترى العربة تعبر من نقطة البداية إلى الهدف. تعرض اللعبة المشهد بمجسمات WebGL ثلاثية الأبعاد بخامات خشب وخرسانة وماء، ويمكن تدوير زاوية الرؤية بسحب المشهد؛ إذا لم يدعم المتصفح WebGL، تبقى الرسوم ثنائية الأبعاد بديلًا. تتدرج اللعبة في عشرة مستويات لتعليم تسلسل الأوامر، التكرار، شروط إذا/وإلا بحسب حالة النهر، وتصحيح الأخطاء واختصار البرنامج. تعرض المستويات تلميحات تناسب مراحل عمرية تقريبية (6–8، 9–11، 12–15) من دون منع أي طفل من تجربة التحديات.

تُحسب النجوم وتُعرض بصورة مستقلة لكل لعبة، بينما يعرض ملخص المنصة مجموع نجوم الألعاب.

## إضافة لعبة
أضف صفحة اللعبة داخل `pages/` ثم أضف عنصرًا إلى `gameCatalog` في `pages/common.js` يتضمن المفتاح والعنوان والرمز والرابط وعدد المستويات واللون. سيظهر العنصر تلقائيًا في قسم الألعاب، ويدخل عدد مستوياته في ملخص التقدم.

### تثبيت التطبيق على الهاتف

يدعم الموقع التثبيت كتطبيق ويب (PWA). انشره على HTTPS؛ التثبيت عبر الهاتف يتطلب اتصالًا آمنًا (ويُستثنى localhost للتجربة على الكمبيوتر). في Chrome أو Edge اضغط «تثبيت التطبيق» ثم وافق على نافذة التثبيت؛ يجب تأكيد التثبيت من المتصفح ولا يمكن تجاوزه برمجيًا. عارض VS Code لا يدعم نافذة التثبيت، لذا افتح رابط الموقع في Chrome أو Edge. في iPhone/iPad افتح الموقع في Safari، واضغط «مشاركة» ثم «إضافة إلى الشاشة الرئيسية». تظهر إرشادات التثبيت أسفل الزر عند الحاجة.

## إدارة المستخدمين وحفظ تقدمهم سحابيًا

يعمل الموقع الثابت على GitHub Pages مع Firebase Authentication وCloud Firestore لحفظ تقدم كل حساب تحت UID الخاص به، واستعادته عند تسجيل الدخول من جهاز آخر. يتطلب إنشاء الحساب وتسجيل الدخول برمز PIN المكوّن من 4 أرقام نشر Cloud Functions؛ ويُخزّن الرمز كقيمة مشتقة ومملحة في مجموعة `accounts` ولا يُحفظ كنص مكشوف في ملف المستخدم أو قاعدة البيانات. للحسابات المحلية على الجهاز، يُشتق الرمز باستخدام PBKDF2 قبل حفظه في `localStorage`. يختار المستخدم الاسم واسم المستخدم والرمز والشخصية والدور (طفل أو معلم أو ولي أمر)، ويُفعّل الدور مباشرة عند التسجيل. الرمز القصير أسهل للتذكر لكنه أقل أمانًا من كلمة المرور؛ تحد خدمة الدخول السحابية المحاولات الخاطئة إلى 10 محاولات لكل اسم مستخدم وعنوان IP خلال 15 دقيقة. تبقى كلمات المرور القديمة الأطول صالحة للحسابات المنشأة سابقًا. يحوّل التطبيق اسم المستخدم إلى معرّف بريد افتراضي بالشكل `username@accounts.kids-games.invalid` لا يستقبل الرسائل.

تتيح لوحة المدير السحابية البحث والتصفية وتعديل أدوار الحسابات وحالتها. إنشاء حساب المدير الأول وحذف الحسابات تتم من Firebase Console. عند نقل حساب قديم، حدّث بريده في Firebase Authentication إلى المعرّف الافتراضي أعلاه واضبط كلمة مرور له مع الاحتفاظ بـ UID نفسه؛ يدمج التطبيق التقدم المحلي القديم عند أول تسجيل دخول.

يمكن لكل مستخدم فتح «ملفي الشخصي» من قائمة الحساب لتغيير الاسم والشخصية. كما يمكن للحسابات المحلية تغيير رمز PIN ذي 4 أرقام أو كلمة المرور الحالية؛ يتطلب تغيير بيانات الدخول السحابية نشر Cloud Function `updateOwnProfile`، ويمكن للحسابات السحابية القديمة إعادة التحقق بكلمة المرور الحالية. الحسابات المرتبطة بـ Google تغيّر كلمة مرورها من Google، ويمكنها تعديل الاسم والشخصية من التطبيق.

### تجهيز Firebase للنشر

1. أنشئ مشروع Firebase، وأضف تطبيق Web، وأنشئ قاعدة Firestore في وضع الإنتاج. انسخ إعدادات Web العامة إلى `firebase-config.json`؛ هذه الإعدادات ليست مفتاح Admin ولا تحتوي بيانات اعتماد سرية.
2. ثبّت Firebase CLI، وسجّل الدخول، واختر مشروعك من مجلد المشروع:

   ```powershell
   npm install -g firebase-tools
   firebase login
   firebase use --add
   ```

3. فعّل مزوّد Email/Password في Firebase Authentication. يتطلب نشر Cloud Functions خطة Firebase مع فوترة مفعّلة وقد تترتب عليه تكاليف حسب الاستخدام؛ راجع أسعار Firebase قبل النشر. بعد ذلك انشر الدوال وقواعد Firestore:

   ```powershell
   firebase deploy --only functions,firestore:rules
   ```

4. أنشئ حساب المدير الأول من Authentication > Users في Firebase Console، مستخدمًا مثلًا البريد `admin@accounts.kids-games.invalid` وكلمة مرور قوية. انسخ UID ثم أنشئ مستندًا في Firestore داخل مجموعة `users`، واجعل معرّف المستند هو UID، وأضف الحقول:

   ```json
   {
     "username": "admin",
     "email": "admin@accounts.kids-games.invalid",
     "fullName": "المدير",
     "role": "admin",
     "avatar": "child",
     "provider": "local",
     "status": "active",
     "progress": {}
   }
   ```

   أنشئ بقية المستخدمين من Authentication > Users باستخدام البريد الافتراضي الموافق لاسم كل مستخدم. ينشئ التطبيق ملفاتهم في Firestore عند أول تسجيل دخول، بدور `child`.

5. سجّل الدخول باسم المستخدم `admin` وكلمة المرور التي أنشأتها. الحسابات التجريبية القديمة في `localStorage` ليست حسابات سحابية؛ أنشئها في Firebase Authentication واضبط البريد الافتراضي وكلمة المرور يدويًا. يمكن للحسابات القديمة استخدام كلمة مرورها، أما الحسابات الجديدة فتستخدم رمز PIN من 4 أرقام.
6. انشر ملفات الموقع إلى GitHub Pages. لا يحتاج نشر الموقع إلى Firebase Hosting.

### التحقق والأمان

- لا ترفع `node_modules` أو بيانات اعتماد خاصة إلى GitHub. يعتمد نشر Cloud Functions على الحزم المعرفة في `functions/package.json`.
- تسمح قواعد Firestore للمستخدم بالوصول إلى ملفه وتقدمه فقط. يختار الحساب الجديد دور طفل أو معلم أو ولي أمر عند التسجيل، ويُمنع تغيير الدور بعد ذلك إلا بواسطة المدير. لا يمكن إنشاء حساب مدير من واجهة الموقع؛ ويُحدد المدير الأول يدويًا من Firebase Console.
- المستوى التالي لا يُفتح للمستخدم غير المدير إلا بعد إكمال السابق في اللعبة نفسها؛ ويستطيع المدير فتح كل المستويات.
- تحتوي صفحة الدروس على خمسة دروس جاهزة برسوم توضيحية محلية في الأوامر والتسلسل والتكرار والشروط وتصحيح الأخطاء. يحدد المدير من لوحة الإدارة عدد المستويات المكتملة المطلوب لفتح كل درس؛ وتُحفظ الإعدادات سحابيًا مع Firebase أو محليًا عند عدم تفعيلها.
- إذا لم تُملأ إعدادات `firebase-config.json` أو لم تُنشر القواعد والدوال، يعمل تسجيل الحساب محليًا فقط ولا توجد مزامنة سحابية؛ تُحفظ الحسابات المحلية على الجهاز نفسه فقط.
